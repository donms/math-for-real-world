## 1. ★★★ 面积多读一位 —— "28 万 ㎡"被读成"282 万 ㎡"

**症状**：算出**单位成本 0.56 元/㎡·月**，而住宅收费是 **4.91 元/㎡·月**

**★ 最要命的是**：用户转发的文章里**明写着「一个管着近 1900 户、
28 万平方米的品牌物业项目」** —— 我**没有拿它去交叉验证**。

并且 `p0_area_check.py` 里做了**四条独立约束的判别**
（户均建面合理区间 / 面积×单价=收入 / 年收入量级 / 成本<收入），
**口径 ② 全通过**，其余不通过。

> ★★ **教训（值得写进 skill）**：
> **算出一个反常识的数时，先怀疑自己的输入，而不是去构造解释。**
> 我当时的第一个反应是"这表单位混用了，要写个脚本判别单位" ——
> 而真相是我自己读错了一位。

## 5. ★★★ 利润差 2 600 元/月 —— **我先归因错了方向，后来定位到"收入侧"**

| 项 | 值 |
|---|---|
| 收入 − 支出 | 1 583 994.24 − 1 576 960.74 = **7 033.50** |
| 表给利润 | **4 433.50** |
| **差** | **2 600.00 元/月（年 31 200）** |

### 我最初的做法（**错的**）

1. 查"支出侧有没有哪一行等于 2 600" ⇒ **没有**；
2. 看到报道文章说"这还没摊总部的管理费、品牌费"；
3. **就采信了它** —— 写成"这 2 600 是表外的总部/品牌费"。

### 错在**只验了一端**

**总部管理费与品牌费属于支出侧，而我说不出它在支出表的哪一行** ——
这个矛盾我当时没追。正确的做法是**把两端的合成都验一遍**：

| 项 | 值 |
|---|---|
| 物业费小计 | 1 432 894.24 |
| 停车费（2 475 × 60，已单独验过 ✓）| 148 500.00 |
| **两者之和** | **1 581 394.24** |
| **表给「收入月费用」** | **1 583 994.24** |
| **差** | **★ +2 600.00**（与利润差额**完全相同**）|

**⇒ 这 2 600 在「收入侧」**：表里的"收入月费用"比已列明的两项之和**多 2 600**。

**再排除**：反推隐含停车费 = 151 100，而 $2\,475\times61.05=151\,098.75$、
$2\,518\times60=151\,080$ —— **用整数车位乘常见单价凑不出**。

**⇒ 最可能是表内未单列的某项收入（公共收益）。表内不可判定，如实留档。**

**★ 并且必须修正那个流行说法**：文章说"还没摊总部管理费、品牌费"——
**但该差额在收入侧，而总部费用属支出侧 ⇒ 这个说法解释不了它。**

### ★★ 由此提炼的方法（已写进论文 §5.4.4）

```
发现 A − B ≠ C
  ① 先验 A 自身的构成（A 是否等于它该等于的各项之和？）
  ② 再验 B 自身的构成
  ③ 只有 A、B 各自都验通之后，差额才落在 C 上
```

**跳过 ①② 直接解释 C，会把"某一端多列了"误判成"另一端少列了" —— 方向正好相反。**

## 6. ★★ 成本随规模"次线性"增长 —— 我第一版模型算出了荒谬结果

**症状**：第一版的"小地块"模型里，
**100 户小区需要 20.60 元/㎡·月**才保本（是现行的 4.2 倍）。

**根因**：我把"按小区配置的固定成本"当成**与规模无关的常数**
（176 831 元/月）⇒ 100 户小区也被摊上 **1 768 元/户·月**。
**而 100 户小区不可能有 17.7 万/月的成本编制。**

**修法**：改成 **`C(N) = C_floor + k·N^α`（α < 1）**，
`C_floor` 也随规模同阶缩放，用**当前规模定标** `k`。

**★ 但第二版仍有问题**：临界户数算出 **1 849 户**（而当前 1 867 户），
**余量只有 1%** —— 这个结论**过于依赖我拍的 `C_floor` 与 `α`**，
**必须用真实的小地块数据标定**（见 `probe_*` 的三条路）。

## 14. ★★ 我自己的模型写错过一次：把"比率"当成了"绝对量"

**症状**：算"规模不足 ⇒ 费用摊不开"时，
我写 `F = 收入 × 5.21%`（5.21% 是中指数据里"中小 vs 头部"的**费用率差**）。

**根因**：**5.21% 是比率**。比率 × 收入 ⇒ F **与收入成正比**、
也就是**与户数成正比** ⇒ `F/N` **恒等于 43.3**，
**完全没有规模效应** —— 而我想证的恰恰是"有规模效应"。

**修法**：**放弃强行拟合**，改为**罗列真实案例数据点**
（上海虹桥镇 / 杨浦定海路的街镇级普查、成都 64–169 户个案），
并明确写出"参数标定所需的数据免费渠道拿不到"。

> ★★ **教训：建模时先问"这个量是比率还是绝对量"。**
> 把比率当绝对量用，会得到一个**看起来有公式、实则无关系**的模型。
> **而且它不会报错 —— `F/N` 照样算得出一个漂亮常数。**
>
> 配套判据：**算完先看"这个量随规模变不变"**。
> 若一个号称反映规模效应的量在 5 万㎡ 与 100 万㎡ 下**完全相同**，
> 那它一定没有反映规模效应。

## 16. ★ 分层抓取"静默空转"：跑 4 分钟不输出、不写盘

**症状**：v1 分层抓取启动后，**4 分钟一个字都不打印、数据文件也不增长**。
而 API 实测 **0.2 秒/请求**（没有被限流）。

**根因（两条叠加）**：

1. **脚本在某些格子上不出数时不打印**（`new` 为空就 `break`，无日志）
   ⇒ **看起来像卡住，其实在正常空转**；
2. **输出被管道缓冲** —— PowerShell 的 `| Select-Object -Last N`
   会缓冲 Python 的 stdout ⇒ **即使打印了也看不到**。

**修法**：
1. **每个格子无条件打印一行**（公告数/新数/宗地数/耗时）；
2. ★ **用 `python -u`**（或 `flush=True`）—— 本脚本两者都做了。

> ★★ **教训：长任务必须"每步可观测"。**
> `flush=True` + 每格一行日志，比事后猜"是不是卡了"便宜得多。
> **另外：`| Select-Object -Last N` 会吞掉中间输出** ——
> 跑长任务时**不要用它**，或者直接用 `python -u`。

## 19. ★★★ 共享脚本 `render_video.py`：回退分支的判据不全（**影响所有期**）

**症状**（未配音的期跑 `--ass-only`）：

```
TypeError: float() argument must be a string or a real number, not 'NoneType'
  build_ass → d_i = float(cap.get("dur", 0))
```

**根因**：`build_ass` 的兼容注释只写了**两种** `captions`：

| # | 形态 | 旧代码是否处理 |
|---|---|---|
| ① | `dict` 列表 + `dur` **有值**（配音后）| ✅ 走"逐条严格对齐" |
| ② | **`str` 列表**（很旧的 manifest）| ✅ 走回退 |
| **③** | ★ **`dict` 列表但 `dur` 是 `None`**（`make_render_specs` 刚生成、还没配音）| **❌ 漏了** |

而 `make_render_specs.py` 产出的正是 ③
（`"captions": [{"text": c, "audio": None, "dur": None}]`）。
旧判据 `if caps and isinstance(caps[0], str): caps = None` 对 ③ **不成立**
⇒ 落到"逐条严格对齐"分支 ⇒ `float(None)` 崩。

**修法**：判据改成「**只要有一条 `dur` 缺失就走回退**」

```python
_caps_ok = bool(caps) and isinstance(caps[0], dict) and all(
    isinstance(c.get("dur"), (int, float))
    and not isinstance(c.get("dur"), bool) for c in caps if isinstance(c, dict))
if caps and not _caps_ok:
    caps = None
```

> ★★ **教训：写"兼容多种输入形态"的分支时，要问
> "我枚举的形态全吗？" —— 而"字段值可能是 None"这一种最容易被漏。**
> 枚举形态时要按「**类型 × 值是否缺失**」两维列，不是只按类型列。

## 20. ★★★ 共享脚本 `make_render_specs.py`：小节别名不全 ⇒ **7 屏里 4 屏念同一句**

**症状**：抖音配音日志里，第 4–8 段念的**全是**「完整算账过程在视频里。」
即 7 屏口播里 **只有 4 条不同**：

```
不同口播条数: 4 / 7
```

**而且全程不报错**（时长、字幕、同步校验全部正常）。

**根因**：它找口播稿那一节用的是

```python
k = txt.find("口播稿")
```

而实际稿件标题写的是 **「## 口播脚本」** ⇒ `find` 返回 **−1**
⇒ `seg = txt`（**整篇**）⇒ 取**第一个代码块** ⇒
抓到的是「**发布文案**」那个块（4 段）

⇒ 段落数 4 < 屏数 7 ⇒ 末尾几屏用兜底（重复最后一段）。

**修法**：多别名 + 优先取 `## ` 标题命中处

```python
k = -1
for _alias in ("口播脚本", "口播稿", "口播文案", "逐屏口播"):
    _k = txt.find(_alias)
    if _k >= 0:
        k = _k
        break
```

**并且**：`make_screenplan_douyin.py` 的出口处**断言段数 == 屏数**；
同时在 `内容/抖音.md` 里把"口播脚本"这一节的**段内换行合并成一行**
（解析器按空行切段，段内换行会被当成两段）。

> ★★ **教训：凡是"按标题关键词定位取块"的解析器，
> 都要问"标题换个写法它还认吗"—— 并从内容侧**统一用同一个词**。**
> 这类失败的典型特征是**不报错、数量对不上**，
> 所以必须有"**数量断言**"（段数 == 屏数、口播去重后条数 == 屏数）。

## 21. ★★ `cards_<期号>.json` 被**两个平台争用**（小红书 vs 抖音）

**症状**：我按小红书（1080×1440、6 张）写好了 `publish/cards_2026-W54.json`，
渲染出图后，重跑 `make_render_specs.py` ——
**它把抖音卡片（1080×1920、7 屏）写进了同一个文件名**，
我的小红书清单**被静默覆盖**。

**根因**：两个渲染器共用一套命名约定：

| 用途 | 清单 | 尺寸 |
|---|---|---|
| 小红书图文 | `publish/cards_<期>.json` | 1080×1440 |
| 抖音视频素材 | **同一个文件名**（由 `make_render_specs` 重写）| 1080×1920 |

**修法**：拆成两份**语义明确**的清单：

* `publish/cards_xhs_<期>.json` —— 小红书（**手写**，不被任何脚本重写）
* `publish/cards_<期>.json` —— 抖音（**由 `make_render_specs` 生成**，不手改）

并用 `render_cards.py --spec <绝对路径>` 显式指定小红书那份。

> ★★ **教训：「同名文件被两个流程写」是静默数据丢失的经典形态。**
> 一个文件若既是"人写的输入"又是"脚本的产物"，它一定会被覆盖。
> **⇒ 输入与产物必须不同名。**

**并且**：`render_cards.py --spec` 的路径是**相对 cwd** 解析的
（不是相对期目录）⇒ 跨目录调用**必须给绝对路径**，
否则报 `[!] 清单不存在: <LOCAL_PATH>
`--out` 亦然（相对清单目录）。

## 22. ★★ `summary` 卡只显示 1 条要点 —— 因为 `lines` 被 `sub` 兜底

**症状**：抖音第 7 屏（summary）本应显示 3 条要点，实际**只有 1 条**。

c["lines"] = extra.get("lines") or ([sub] if sub else [head])

## 23. ★★ `add_voice.py --reuse` 必须显式指定引擎（否则找错扩展名）

**症状**：

```
[!] 屏01 第1条 音频缺失，已跳过：s01_01.mp3
（全 110 条都报缺失，纯语音合计 0.0s）
```

而 `publish/配音/bili/` 里**明明有 110 个 `s01_01.wav`**。

**根因**：`--engine` 默认是 **`edge-tts`** ⇒ 期望扩展名 `.mp3`：

```python
ext = ".wav" if engine in ("indextts", "gptsovits") else ".mp3"
plan.append((i, j, cap_sub, cap_say, vdir / f"s{i:02d}_{j:02d}{ext}"))
```

用 indextts 配的音是 `.wav` ⇒ `--reuse` 时若不给 `--engine indextts`，
它就去 `.wav` 的位置找 `.mp3` ⇒ **全部"缺失"**。

**修法**：

```powershell
$PY scripts\add_voice.py --root episodes/<期> --variant bili --engine indextts --reuse
```

> ★★ **教训：`--reuse` 的语义是"按引擎约定的文件名去找现存音频"，
> 它依赖 `--engine`。⇒ 凡是用过一次 `--engine X`，之后所有命令都要带上它。**
> 更稳的做法：让脚本**自动探测**（目录里既有 `.wav` 又有 `.mp3` 时按实际存在的选）。

### 附：两个配音目录的语义（我一开始也搞混了，白挪了一轮）

| 目录 | 角色 | 谁写 |
|---|---|---|
| `publish/配音/<变体>/` | **原始音频**（`--reuse` 找这里）| 合成时 |
| `publish/配音/<变体>_clean/` | 裁掉首尾静音后的**派生品** | `build_clean_audio()` |

**⇒ 千万不要把 `_clean` 当成原件目录。**
