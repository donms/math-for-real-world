## 一、★ 验证 ODE 守恒：判据要建在"可达状态"上（**本期最大的坑**）

**症状**：12 维模型在随机状态下 `sum(dy) = 0.38~0.43`，看起来严重不守恒；
我据此**花了好几轮去"修守恒"**（改了恢复入流的写法四次）。

**根因**：随机 Dirichlet 状态**不是这条 ODE 能到达的**。
`rhs` 里有 `np.maximum(y, 0)` 钳位，那些状态落在钳位边界上，
分支一开一合就造成不连续 —— **与模型对错无关**。

**修法**：判据改成**在真实轨迹的状态上查**：

| 判据 | 结果 |
|---|---|
| 随机 Dirichlet 状态（假阳性）| 0.38 ~ 0.43 |
| **真实轨迹状态** | **1.04e-17** |
| 12 年积分漂移 | **3.11e-15** |

**通用教训**：
> **验证 ODE 的守恒性，不能用"任意合法的概率单纯形点"，
> 要用"从初值出发实际到达的点"。** 前者会给出大量假阳性。

## 二、★ 剖面似然：三次失败，最后靠"降维 + 自检"做对

### v1 惩罚项钉参数 => 区间恒为 0

**症状**：`pen = ((θ_j - v)/v)² × 1e9`，所有参数的 95% 区间都是
**零宽度**（R0 给 `[1.549, 1.549]`）。

**根因**：惩罚太强 => 优化器在 θ_j 方向**根本走不动** =>
剖面退化成"在起点原地取似然" => 区间必然是 0。

### v2 降维了，但起点"按位置"对齐 => 参数错位

**症状**：自检"固定最优值给 **2731**，应为 **459**"。

**根因**：构造自由参数起点时按 `n == 'theta'` 判断，
而 `'R0' != 'theta'` => 对 R0 也取了 log => **整体错位一位**，
`x_full` 变成 `[0.43, -27.6, -27.6, 49.4, -27.6, -27.6]`。

### v3 修法（两条一起）

1. **起点按名取**：`x0f = [to_x(pv)[FIT_NAMES.index(n)] for n in free]`
   —— 按位置对齐就永远可能错位，按名字不会；
2. **全程只用一本"对数尺度字典"**，不要在中间混用自然尺度；
3. **子优化器换 Powell**（见下）。

### v4 子优化器：L-BFGS-B 在噪声目标上不动

**症状**：剖面网格上 `d_sse` **全在 800–2300**，而最优是 459。

**根因**：SSE 由 **ODE 数值解 + 插值**得到，函数面**有数值噪声**；
L-BFGS-B 的**有限差分梯度被噪声淹没** => 原地不动。
（实测：换成 Powell 后 `d_sse` 立刻降到 **−0.37**。）

### ★ 元教训：**自检机制**

在剖面循环里加一条**必需通过的自检**：

> 把参数固定在**最优值**上、自由参数从最优出发，**必须复现 best_sse**。

**这个自检两次抓出了真 bug**（v2 的错位、v4 的不收敛）。
**没有它，我会把"零宽度区间"当成"参数不可辨识"写进论文。**

## 三、★ 诊断脚本自己会出错：一次错误结论与一次错误归因

### 3.1 把"似然面上升"误判成"噪声地板过高"

**症状**：诊断脚本用 `max(deltas)`（大扰动下的 ΔSSE = **7.79**）
当"噪声地板"，判"地板 >> 3.84 => 剖面不可用"。

**根因**：R0 扰动 0.003/0.01/0.03 给 ΔSSE **0.097/0.48/7.79** ——
这是**光滑似然面的正常上升（信号）**，不是噪声！

**修法**：地板要取**最小可用扰动**（$10^{-4}$）处的 $|\Delta$SSE$|$
= **6.8e-5**，比阈值小 5 个数量级。

### 3.2 前两版诊断脚本**各自重算了一遍转移公式**

**症状**：同一状态下"诊断式"算出净 −0.497，
而**直接对 `rhs` 求和**得到的残差未必相同 => 误导性归因。

**修法**：**验证脚本不要重算流量**，只信 `rhs` 的输出 + 有限差分。

### 3.3 ★ 从**一张图**给耦合动力系统下结论

**症状**：看到**一组默认参数**的正演图，我目测断言
"**竞争排斥**（株1份额→0）"与"**模型缺年际变异**"，并准备写进论文的"模型失败"一节。

**量化后三条全部不成立**：

| 检查 | 目测 | 实测 |
|---|---|---|
| 两株共存 | 竞争排斥 | 株1份额 **0.000~0.986**，**5/8** 组参数共存 |
| 年际变异 | 模型缺变异 | 模型 CV **0.422** vs 数据 **0.355** |
| 份额振幅 | 份额不动 | 模型 sd **0.285** vs 数据 **0.236** |

**通用教训**：
> **不能用一张图（尤其一组参数的图）给耦合动力系统下结论。**
> 先定量化判据，再测。（$\phi=1$ 时份额恒 0.5 是对称退化，正常。）

## 四、★ 变点检测：众数落在边界 != 估计值

**症状**：族 I（前段常数 + 后段常数）在**四个窗口**上的众数
**全部落在允许范围的边界**（35 / 4 / 43 / 43）。

**根因**：去季节后序列**先降后升**，而该模型强制"前段平 + 后段常数"
=> **只能靠把断点推到端点来近似**。
（诊断：边界后验 0.251/0.600/0.588/0.705，均 > 内部最大。）

**修法**：换成**允许两段各有斜率**的模型，立刻得到内部极值。

**通用教训**：
> **变点检测必须显式检查"众数是否落在允许范围边界"。**
> 判据：**边界处后验 > 内部最大后验 => 报告"不可辨识"**，
> 而**不是**报告那个边界位置。

## 五、优化器选择：梯度法 vs 单纯形法差 34 倍

| 优化器 | 单起点评估次数 | 耗时 | SSE |
|---|---|---|---|
| Powell / Nelder-Mead（7 维，maxiter=600）| 数千 | **>20 分钟** | — |
| **L-BFGS-B**（maxfun=400）| **184** | **17 秒** | **更低** |

实测：Powell 跑 23 分钟**连第 1 个起点都没跑完**。

**通用教训**：**光滑、低维、可数值求导的问题，永远优先梯度法。**
单纯形法在维数 >=6 时评估次数会爆炸。

**但反过来**：**有数值噪声的目标函数**（如本节第二部分的剖面）
要让位给**无梯度法**。**两件事不矛盾 —— 判据是"函数面光不光滑"。**

## W46-补记 ★★★ **改一两屏不需要全量重配** —— 我误判了 `--pages`

### 起因（用户提出）

> 「为什么每次改一两屏的内容，就得**全量配音加渲染**？
> 就算 IndexTTS 每次同样字幕生成的语音长度有变化，
> 难道不应该**只把变化的内容重新配音**，然后确定每一屏的时长，再渲染视频就行了？」

**用户是对的，我错了。**

### 我先前说了什么

在改 W46 屏 14/15 时，我明确说过：
「`--pages` 只过滤合成列表，**但清单仍写全部段**，其余段会报"音频缺失"
=> 不能用于"只补几条"」，并据此做了**全量重配（约 25 分钟）**。

### 实测推翻（2026-10-10 受控实验）

`add_voice.py --pages 15`，然后**逐条比对清单**：

| 检查项 | 结果 |
|---|---|
| 屏数 | before **22** / after **22**（**完整保留**）|
| `audio=None` 的条数 | **0**（其余屏**没被清空**）|
| 音频**内容**变化条数 | **0** |
| `配音/bili/s15_*.wav` 时间戳 | **更新到本次运行时刻** |
| `配音/bili/s01_*` `s14_*` `s16_*` 时间戳 | **仍是几十分钟前** => **未被重合成** |

**并且代码注释本来就写着**（`add_voice.py` 的 `--pages` 分支）：

    # ★ --pages：只把目标屏的段交给引擎，其余段落的 raw wav 原样保留
    #   （IndexTTS 走批量合成，故过滤列表即可；下游 clean/时长实测自然不变）

**=> 我误读了自己的脚本注释。**

### 实测成本对比

| 做法 | 耗时 |
|---|---|
| **全量重配（我做的）** | **约 25 分钟** |
| **`--pages 15` 局部重配** | **1–2 分钟** |
| 渲染（整段 filter_complex 重编） | **84 秒**（757s 成片）|
| **正确做法合计** | **约 3 分钟** |

### ★ 但确实有一个真陷阱（这才是我该提醒的）

**先跑 `make_render_specs.py` 会重建 manifest，把 `captions[].audio` 与 `dur`

**今天我就是先跑了它，然后才发现"音频没了"** —— 于是误以为是 `--pages` 的问题。

### 正确的"改一屏"顺序

| # | 动作 | 说明 |
|---|---|---|
| 1 | 改 `内容/讲稿.md` | 只改该屏口播 |
| 2 | **不要**跑 `make_render_specs.py` | 它会清空音频链接 |

| 5 | `add_voice.py --pages <N>` | **只重配该屏** |

再 `--pages <N>` 改目标屏，最后渲染。

## W46-补记 2 ★★★ **音频与字幕错位 —— 我自己"修复"出来的**

> 用户：「看了下 b 站的视频，音频和字幕不同步」

**详见 `_logs/音频字幕错位事故.md`。此处只记结论与教训。**

### 链条

1. 清单缺 `tts_captions` => `add_voice` 落兜底、**把口播当字幕**（用户第 1 次报告）；
2. 我补上 `tts_captions` 并修 captions 结构 => 字幕形态对了；
3. 但 `--reuse` **用自己的 max_cap 重切了 captions**（116 -> 109 条）；
4. ★ 我为"条数配对"，**把 `tts_captions` 重写成 `[to_tts(c) for c in captions]`**
   —— **只改声明，没重新合成音频**；
5. 只重配 7 屏，其余 16 屏沿用旧音频 => **全片错位**。

### 决定性证据

`probe_sync_by_resynth.py`：把当前 `say` 重新合成，与现有音频比时长 ——
**8 段抽样 5 段不一致**，最大偏差 **+5.32s**（屏 20#1 只说了应说内容的一半）。

### ★ 教训：**改了"声明"，没改"实体"**

* `tts_captions` 是**声明**（"这段音频对应这些字"）；
* `配音/*.wav` 是**实体**。
* 只改声明 => **声明与实体脱钩**，
  而所有**静态检查全部通过**（条数配对、时长自洽、ASS 一致）
  —— 因为它们**只检查声明**。

> **这就是"检查全绿"却仍然错位的原因。**

**规则**：任何改变"分段/文本"的操作，**必须重新合成对应音频**；
做不到就**不要改分段**。

### 我在诊断上走的弯路（四版判据，前三版都错）

| 判据 | 问题 |
|---|---|
| `_timing.txt` 字数 vs 清单字数 | 该文件是显示形态+实际重切文本，与 `say` 天然不同 |
| `_timing.txt` 时长 vs 清单 `dur` | 对得上，但只证明"清单=文件"，**不证明文件内容对** |
| 逐段字数 / 时长 = 语速 | **被证伪**：`百分之五点四` 读 7 音节、`R_t` 读 2-3、`1337` 读 5 => 字数模型必然失真 |
| ASS 与 captions 拼接比对 | 只证明字幕与清单一致，**与音频无关** |

**=> 唯一可靠判据：重合成对照。**

### 关于"不要全量重配"

用户之前建议"只重配变化的部分"——**那个建议是对的**，
但它的**前提**是"只改了少数文本、其余音频本来就对"。
本例**前提被我自己破坏了**（切分变了）=> 必须全量重配。

**=> 教训：优化建议要连前提一起记，前提失效时不能机械照搬。**
