## 四、连带修掉的三处缺陷（都在 W46）

| # | 缺陷 | 后果 | 处置 |
|---|---|---|---|
| 1 | `make_storyboard.py` **不产出 `tts_captions`** | `add_voice` 对齐条件恒假 => 落兜底分支 => **把口播当字幕** | 逐条产出 `tts_captions = [to_tts(c) for c in captions]` |
| 2 | `make_render_specs.py` 的 `captions` 是**裸字符串**、白名单拦 `tts_captions` | 清单结构不合规 | 改为 `[{text, audio, dur}]` + 放行 `tts_captions` |
| 3 | `add_voice.py` 兜底分支 `sc.get("tts") or sc.get("text")` **优先取口播** | 一旦落兜底 => 字幕变口播 | 改为**优先 `text`（显示形态）** |

> 缺陷 3 是**根治**：即便将来又落到兜底分支，**字幕形态依然正确**。

## 五、护栏（防复发）

新增 `scripts/check_numeral_hygiene.py`，检查三项：

| # | 检查 | 说明 |
|---|---|---|
| 1 | **模块遮蔽** | 期目录若有与共享脚本同名的**被 import 模块** => 报错 |
| 2 | **单向转换** | `clean_caption` 必须只清标点；`to_tts` 必须转换；`normalize_number_tokens` 必须能抽汉字数字 |
| 3 | **清单配对** | `captions` 与 `tts_captions` 条数一致；`text` 不可是口播形态 |

### 第 3 项判据的演进（**三次误报，记录备查**）

| 版本 | 判据 | 结果 |
|---|---|---|
| v1 | 正则「汉字数词 + 量词」 | **19 处误报**（`一个`/`一起`/`这一期`）|
| v2 | `to_tts` 幂等性 | **15 处误报** —— **`to_tts` 不是幂等函数**（`三周涨六倍多` 无"阿拉伯可转项"，原样返回）|
| v3 | `text == say` | **仍误报**（**不含数字的条两种形态本就相同**）|
| **v4** | **`text` 含阿拉伯数字 且 `text == say`** | **实测 326 条，0 误报** |

**v4 为什么对**：字幕是**显示形态**，若含阿拉伯数字 `3`/`47`/`94.2`，
则口播**必然**已转成汉字 => 两者不可能逐字相同。
反之逐字相同 => `to_tts` **没转** => `text` 被写成了口播版。

## 七、尚存的架构性隐患（**不需要现在改**）

W41–W46 用的是**期目录自带生成脚本**（硬编码版式与画面文字），
W48 起改为**共享脚本 + `publish/screenplan.json`**。

=> **两套架构并存**。旧架构的问题是：
**修了共享模块，期目录的生成脚本不会自动受益**（本次事故正是如此）。

**建议**：新期一律用共享脚本 + `screenplan.json`；
旧期如无必要**不要重跑**（重跑会暴露旧架构的漂移）。
