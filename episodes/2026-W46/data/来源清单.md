# 2026-W46 数据来源清单

> **面向"每个数字都要能溯源"**。本清单记录本期用到的**全部外部数据**，
> 以及实测的**可达性**与**可用性**。
>
> **最近一次更新**：发布前复核时**重新取数**（含 2026W38/W39 两周新数据）。

---

## 一、核心数据

### D1 ★★★ Delphi Epidata · `fluview`（ILI 主序列）

| 项 | 内容 |
|---|---|
| **来源** | Delphi Group（CMU）Epidata API |
| **URL** | `https://api.delphi.cmu.edu/epidata/fluview/?regions=nat&epiweeks={起}-{止}` |
| **实测可达性** | [OK] **稳定**（分批请求，每次 104 周约 2 年）|
| **规模** | **1339 周**，**2000W01 – 2026W39** |
| **取到的字段** | `ili`（流感样病例占门诊比）、`num_ili`、`num_patients`、`wili`、`num_providers`、分年龄段计数 |
| **用途** | 主序列；$R_t$ 反演；季节分解；变点检测 |
| **口径** | **哨点门诊监测**（不是全人群感染率）|

**[!] 两个必须注意的字段细节**：

* **`ili` 的单位是百分数**（如 `1.8285` 表示 1.83%），不是比例；
* **`release_date` 是"该数据的发布日"，不是"该周的日期"** ——
  实测：`epiweek 202637` 的 `release_date` 是 `2026-09-25`，
  而同一条记录在 API 里显示的发布日实为 **`2026-10-09`**（lag 2）。
  => **做"当时能看到什么"的分析（如实时预报）时必须用 `release_date` 过滤**，
  否则会引入**前视偏差**。

### D2 ★★ Delphi Epidata · `fluview_clinical`（分型辅序列）

| 项 | 内容 |
|---|---|
| **URL** | `https://api.delphi.cmu.edu/epidata/fluview_clinical/?regions=nat&epiweeks={起}-{止}` |
| **实测可达性** | [OK] 稳定 |
| **规模** | **522 周**，**2016W40 – 2026W39** |
| **取到的字段** | `total_specimens`、`total_a`、`total_b`、`percent_a`、`percent_b`、`percent_positive` |
| **用途** | A/B 分型占比；双亚型竞争的**观测约束** |

**[!] 局限**：**只有 A/B 两级**，**不含 A(H3N2) 与 A(H1N1) 的细分**。
细分只能从 D3 的少量中国周报里拿。

### D3 ★ 中国流感周报（当期案例，回溯用）

| 项 | 内容 |
|---|---|
| **来源** | 中国国家流感中心「流感监测周报」 |
| **实测可达性** | [OK] 可抓（栏目页 + 逐期 HTML）|
| **规模** | 落盘 **12 期**（`20260702` – `20260926`，对应 2026 年第 26–38 周）|
| **取到的字段** | 暴发疫情起数、ILI%、A/B 占比、部分期含 A(H3N2)/A(H1N1) 细分 |
| **用途** | **当期案例**（"起爆"现象）；也提供少量亚型细分 |

**[!] 关键局限（必须随结论出现）**：

* **栏目页只有 1 页 14 期、无分页、无年份归档、站内搜索 0 条**
  => **历史深度不足**；
* => **12 期不足以估计含季节性的动力学参数**
  （不足一个完整流行季的两倍）。若要用，**必须降到极少参数**并如实说明。

### D4 复核用：流感季口径的对照

| 项 | 内容 |
|---|---|
| **来源** | 本清单 D1 的同一序列（**不引入新数据源**）|
| **做法** | 按**流感季**（约 W40 至次年 W39）切分，而非日历年 |
| **理由** | **CDC 口径**；且实测每个流感季**都是 52–53 周**，而日历年切法**段长不一致** |
| **脚本** | `scripts/q5_recheck_breakpoint.py` |
| **落盘** | `results/核查_口径断点.json` |

## 二、[!] 数据性质与缺陷（**必须随结论出现**）

1. **口径是"哨点监测"，不是全人群。**
   `ili` 的分母是**哨点医院的门诊量** => **分子与分母都受就诊行为影响**，
   不等于真实感染率。**只可做相对比较。**

2. ★★ **2020–2022 是观测口径断点（新冠期）。**
   新冠防控**同时**改变了就诊行为、哨点构成**与**真实传播
   => **观测与真实传播的改动无法分离**。
   实测按流感季的峰值：疫前（<2020，7 季）均值 **5.629**、
   **新冠期（2020-21）3.689（仅疫前 66%）**、疫后（>=2022，4 季）**7.621（135%）**。
   * **2020-21 季必须作为断点单独处理**；
   * **但"疫后没变强"不成立** —— 疫后峰值**高于**疫前，
     且 2025-26 季的 **8.496 是全序列最高**；
   * [!] **疫后升高里有多少是病毒学、多少是行为，本数据分离不了**
     => 只能说"观测到的峰值更高"，**不能说"病毒更强"**。

3. **两套数据的地区与口径不同**（美国哨点 vs 中国周报）
   => **不能直接拼接成一个序列**。

4. **分型只有 A/B 两级** => 双亚型竞争只能建**两亚型**模型。

5. **中国序列太短**（12 期）=> 不足以估计季节性参数。

## 三、拿不到的数据（**如实记录**）

| 缺口 | 实测状态 | 影响 |
|---|---|---|
| **A(H3N2) / A(H1N1) 的长期细分** | 美国序列无；中国周报只有少量 | **无法建"多毒株"模型**，只能 A/B 两型 |
| **中国哨点长序列** | 栏目页无历史归档 | 中国部分只能做**当期案例** |
| **疫苗接种率时间序列** | 未找到可用的长序列 | 免疫水平只能作为**拟合参数**，不能作为已知输入 |
| **病毒基因序列 / 抗原距离** | 未取 | "抗原漂移"只能**间接**从 A/B 占比推断 |
| **人群免疫史的实测数据** | 未取 | 免疫衰减只能**反演**，不能直接标定 |

> [!] 其中**最影响结论的一条**是"A(H3N2)/A(H1N1) 细分拿不到" ——
> 它使"多菌株竞争"这一核心问题**只能退化为 A/B 两型**，
> 而 H3N2 与 H1N1 的竞争恰恰是流感亚型更替的主要机制。
> **这一限制必须写进论文的"模型评价"一节。**
