## 一、★★★ 元胞自动机实现（**最严重的一批**）

### 1.1 整台元胞自动机**从头到尾完全静止**

**症状**：所有车速度恒为 0、位置不变。基本图**画得出曲线**，看起来正常。

**根因**：加速步骤写成了

```python
v = np.minimum(x + 1, vmax)     # ← 错！x 是位置，不是速度
```

**速度被位置钳制**：绝大多数车 `x = 0` => `min(0+1, vmax) = 1`，
再经 `min(v, gap)` 与随机慢化 => **归零**。

**它伪装得极好**：
* 自检「流率随 $v_{\max}$ 单调增」**部分通过**（因为 $\min(x+1,v_{\max})$
  在 $x$ 大时确实随 $v_{\max}$ 变）；
* 基本图**有曲线、有峰值**，肉眼完全正常。

**只有"单车真空测试"暴露了它**（1 辆车、前方全空、必须动起来）：
实测 30 步后位置与速度**全为 0**。

**修法**：改成 `v + 1`。

> **通用教训**：
> **"能跑出曲线"不等于"实现正确"。**
> 元胞自动机/仿真类模型**必须包含"已知答案的极端情形"自检**
> （单车必须动、$p=0$ 时必须单调、自由流速度必须接近 $v_{\max}$）。
> 本期加了 **5 项**自检，第 5 项（能力与饱和度自洽）是被一次
> **自相矛盾的输出**逼出来的。

### 1.2 初速为 0 + 随机布点 => 锁死在堵塞相

**症状**：$p=0$ 的确定性极限下，最大流对 $v_{\max}=1..5$
**全部约 3,390 辆/h** —— $v_{\max}$ 完全不起作用。

**根因**：随机布点产生大量近距离"堵点"；NaSch 每步只允许 `+1` 加速，
而随机慢化不断制造新堵点 => **永远爬不出堵塞相**。

**修法**：**均匀布点 + 初速取 $v_{\max}$ + 预热 >= 8000 步**。

**实测收敛速度**：$\rho=0.004$ 时 **2000 步仍在"爬坡"**
（平均速度还在 1.0 元胞/步）=> 预热窗口必须足够长。

### 1.3 ★★ 环形间距用**车数**取模，而不是**域长**

**症状**：单车时 `gap = 0` => 车永远静止。

**根因**：

```python
gap = (np.roll(x, -1) - x - 1) % len(x)    # len(x) = 车数，不是道路长度
```

环形路里"最后一辆车的前车"是**第一辆车**，其距离要**绕行整条路**。
用 `% len(x)` **只在车均匀铺满整条路时才凑巧对**。

**修法**：传入 `n_cells`，

```python
nxt[-1] = x[0] + n_cells                   # 绕行一圈回到第一辆
gap = (nxt - x - 1) % n_cells
```

> **通用教训**：**环形的取模必须用「域的长度」，不是「样本的个数」。**
> 这两个量在满路上相等 => **错误会被掩盖，只有稀疏情形才暴露**。

### 1.4 「排队消散率」函数测错了对象

**症状**：该函数给出 494 辆/(h.ln)，**远低于跟驰公式的 2,376**。

**根因**：它初始化一个密集车队后测"平均速度 × 密度"，
而**密集车队里平均速度接近 0**（大家都堵着）=>
它测的是**堵塞相的平均速度**，不是**驶出流率**。

**修法**：改用**基本图峰值**（`capacity_from_fd`）。

### 1.5 ★ 输出自相矛盾 => 必须回头查代码

**症状**：同一段输出里，一句是"隧道**远未饱和**"，另一句算出
**饱和度 1.557**（已饱和）。

**教训**：**自相矛盾的输出必须回头查代码，不能就这么报出去。**
它是 1.4 那个错函数的**下游症状** —— 如果我当时只改了措辞，
就会把 1.4 的错一直留在论文里。

**据此加了自检 E**：能力 × 3 得到的饱和度必须落在 $(0,1)$。

## 二、★★★ 建模与口径

### 2.1 把两个不同量纲相减 => 算出"负的分流"

**症状**：反事实基线 **8.33 万辆 < 观测 10.55 万辆** =>
$\Delta_{\text{分流}} = -2.22$（**负的分流**）。

**根因**：把**中秋假期日均**（10.55 / 2.92 / 13.47）与
**全年日均**（88,120 / 65,744 / 98,228）当成同一个量相减。

**修法**：只在**同一口径**内比较，并把趋势作为**显式参数**。

> **通用教训**：**算出来的量落在"不可能区间"（如负的分流、负的流量）
> => 回头怀疑口径，而不是接受它。**
> 这个荒谬值其实是**有用的信号**。

### 2.2 系统最优算出了"违反理论"的解

**症状**：**SO 总时间 419,985 < UE 427,657** ——
违反"系统最优必然是用户均衡的效率下界"。

**根因**：BPR 在 $v/c>1$ 时高度非凸，
**20,001 点网格搜索掉进局部最优**。

**修法**：用**凸规划形式**

$$
\text{UE}:\ \min_{q_T}\Big[\int_0^{q_T}\!c_T+\int_0^{q_B}\!c_B\Big],
\qquad
\text{SO}:\ \min_{q_T}\big[q_Tc_T+q_Bc_B\big]
$$

两者在 $q_T$ 上均**单峰** => 用**三分法**求精确极小。
并把 $T_{\text{SO}}\le T_{\text{UE}}$ 变成**代码自检**。

### 2.3 长度口径不可比 => 结论反向

**症状**：用**跨江段**算自由流时间 => 大桥 1.54 min、隧道 8.87 min
=>「隧道慢 7.33 min」=> 均衡会给出**隧道流量为 0**，与观测 22% 矛盾。

**根因**：隧道的 11.825 km **含两岸接线**，大桥的 3.071 km **只是桥体**。

**修法**：改用**全走廊长度**（大桥 54.5 / 隧道 24.8 km）
=> **隧道反而快 8.64 min，结论完全反向**。

> **通用教训**：**长度/口径不可比时，任何"谁快谁慢"的结论都不可信。**

### 2.4 高峰小时流量的口径判定

**症状**：观测「南向北最高小时流量 7,696 辆/h」，
若直接匹配到单条路上，会得出"超饱和 74%"的错误结论。

**判定方法**（**用模型自洽性，而不是读报道措辞**）：

$$
7{,}696 > \max(C_{\text{大桥}}^{\text{物理}}, C_{\text{隧道}}^{\text{物理}}) = 6{,}600
$$

=> **只能是通道单向合计**。**独立验证**：平均车头时距 $3600/7696 = 0.468$ s，
而三车道 120 km/h 的物理上限约 7,660 辆/h => 同样指向"通道合计"。

### 2.5 官方指标**没有度量定义**时不能当标定目标

「通行效率提升 35%、拥堵里程下降 75%」——报道未给定义。
=> 本文只作**定性对照**，**不进模型**。

### 2.6 差别定价的最优落在**搜索边界**（退化解）

**症状**：脚本报"最优隧道费 0 元"，但我的搜索范围就是 `0,10,15,…,50`
=> **最优落在边界**，说明真实最优在范围之外。

**更重要的是**：这个"最优"是**退化解** ——

| # | 问题 |
|---|---|
| a | 把**全部客车**推向隧道（100%），现实中会立刻过饱和 |
| b | **完全忽略** 143.6 亿元建设成本 |
| c | 把**货车拥堵外部性**全留给大桥，**公平性代价未计价** |

**修法**：在结果里明确标为"退化解"，并写清三项缺失约束。

> **通用教训**：**优化结果落在搜索边界 => 先别报，先问"边界外是什么"。**

## 三、★★ 数据抽取（三个静默错误）

### 3.1 列序按位置取 => 年份整体错位

**症状**：2019/2020/2021 三年的数据**整体错位一格**。

**根因**：源表列序是 **`2021 / 2020 / 2019`（降序）**，
我按 `sorted()` 排成升序却**仍按位置取数**。

**修法**：**按列名对齐**，并用 PDF 印刷的客车占比
（**72.76% / 74.97% / 76.34%**）作**独立校验**（算出来必须一致）。

### 3.2 ★★ 把「北接线」当成「桥体」

**症状**：2024/2025 的车均收入只有 **10.4–11.8 元**，
**低于客车一类收费 25 元**。

**根因**：**2024 年报起公司不再单列「江阴大桥」行**，
我抽到的第一行是 `广靖高速`。查年报 p5「释义」才明白三者是**不同设施**：

| 简称 | 定义 |
|---|---|
| **广靖高速** | **江阴长江公路大桥北接线** |
| **锡澄高速** | **江阴长江公路大桥南接线** |
| **江阴大桥** | 江阴长江公路大桥**本体** |

**修法**：改用（桥体 / 北接线）历史比值外推，并**显式标注为推断**。

> **通用教训**：**算出来的比值落在合理区间外，要回头怀疑口径。**
> 这次的"不合理值"（车均 10.4 元 < 最低收费 25 元）是唯一的报警。

### 3.3 「表格页」的判定条件太松

**症状**：定位"江阴大桥表格页"时命中了 p68 —— 那是**文字介绍页**
（提到"江阴大桥"且别处有"客车流量"字样），并不是表格页 => 后续找不到标签行。

**修法**：改成必须**同时**有「独立的『江阴大桥』标签行」与「以『客车流量』开头的行」。

### 3.4 临时目录路径少写一层

**症状**：所有年份都报"未找到年报 PDF"。

**根因**：写成 `<LOCAL_PATH>
实际在 `.\.workbuddy\tmp\w47`。

**修法**：`Path` 多候选探测 + **写死路径前先 `Test-Path` 验证**。

### 3.5 期 README 的标题是占位符

**症状**（W44 已推送后才发现的缺陷）：期 README 写成
「本仓库对应 **2026-W44** 期：**2026-W44 期**」。

**根因**：`make_github_pack.py` 有个 `TITLES = {...}` 登记表，
**W44/W45 没登记** => 回退成 `f"{ep}"`。

**修法**：补登记 W44/W45/W46。

> **通用教训**：**每期做完就去 `TITLES` / `BLURBS` 登记**，别等打包时才发现。

### 3.6 ★ 汇总脚本猜键名 => 静默打印 0

**症状**：`make_summary.py` 里 `q3["标定"]`（该键不存在），
`.get(...)` 返回 `None` => 打印出 **`0 辆/h`、`0.00`**，
**而这两个 0 会被当成真实数字写进"数字弹药库"**。

**修法**：改成**取不到就报错**：

```python
if not base:
    raise SystemExit("[X] 找不到隧道能力条目 —— 键名变了？请核对后再生成")
```

> **通用教训**：**汇总型脚本里，`.get(key, 0)` 是危险默认值。**
> 数字的"缺失"与"真的是 0"必须区分开。

## 四、★★ 工具链与格式

### 4.1 嵌套 ASCII 引号（**本期犯了 6 次**）

**症状**：`SyntaxError: invalid syntax. Perhaps you forgot a comma?`

**根因**：在 f-string 里写中文时用了英文双引号，例如

```python
print(f"…所以"让客车留在桥上"不再是最优…")
```

**修法**：中文引号用 `「」` / `『』` / `""`。

> **有效习惯**：**每次改完立刻跑 `scripts/_lint_episode.py`（AST 扫描全部 .py）。**
> 本期它抓到了全部 6 次，比运行时报错早得多。
>
> **但要注意**：`_lint_episode.py` 只扫 `.py` 文件 ——
> 我用 `python -c "…"` 写的**内联补丁脚本**它扫不到，
> 所以我一度看到"0 个语法错误"却在同一条命令里报错，**造成困惑**。
> => 复杂改动**落成脚本文件**，不要用内联命令。

### 4.2 PowerShell 的 `Set-Content -Encoding UTF8` **会写 BOM**

**症状**：`ssh` 报 `Bad configuration option: BOM host`。

**修法**：用 .NET 显式写无 BOM：

```powershell
[System.IO.File]::WriteAllText($path, $cfg,
    (New-Object System.Text.UTF8Encoding($false)))
```

**验证**：首字节应为 `72,111,115`（`Hos`），不是 `239,187,191`。

### 4.3 GitHub HTTPS 被墙，SSH 可用

**症状**：`Failed to connect to github.com port 443`（**5 次测只通 1 次**）；
`api.github.com` 连接被关闭。

**诊断**：`github.com:22` **4/4 通**、`ssh.github.com:443` **4/4 通**
=> 改走 **SSH**。

### 4.4 沙箱禁止命名管道 => `git push` / `git ls-remote` 失败

**症状**：

```
sh.exe: *** fatal error - couldn't create signal pipe, Win32 error 5
```

**根因**：Git-for-Windows 调 `sh.exe`，它需要**命名管道**，而沙箱禁止。
**注意**：`ssh -T git@github.com` **能成功**（不调 `sh.exe`），
只有 `git` 的远端操作才失败 —— 容易误判为"认证问题"。

**修法**：对**这一条推送命令**申请一次性提权。

### 4.5 SSH 子进程在沙箱内 => 读不到沙箱外路径

**症状**：`Permission denied (publickey)`，即使密钥正确。

**根因**：`git` 启动的 `ssh` **子进程在沙箱内运行**，
`<USER_HOME>\.ssh` 只读 => **无法写 `known_hosts`**。

**修法**：把可写部分放到**工作区内**，用 `GIT_SSH_COMMAND` 指定配置：

```powershell
$env:GIT_SSH_COMMAND = "ssh -F <LOCAL_PATH>"
```
其中 config 里 `UserKnownHostsFile <LOCAL_PATH>
`IdentityFile` 仍指向沙箱外的私钥（**读**是允许的）。

### 4.6 沙箱拒绝在工作区内 `icacls` / `Remove-Item`

**症状**：`icacls` 报 Access denied；`Remove-Item` 后文件仍在（0 字节的 `.pub`）。

**影响**：无法把私钥 ACL 收紧成 `ssh` 接受的形式 =>
**放弃"在工作区新建密钥"的思路，改用已注册的那把**。

### 4.7 sse.com.cn 有 JS 反爬

**症状**：请求 `static.sse.com.cn` 的 PDF，返回 **gzip 压缩的 HTML**
（内容含 `acw_sc__v2` cookie 挑战、`arg1='4DA85EFC…'`），
`gzip.decompress` 后是 0.01 MB 的 `<html>`。

**修法**：改走**巨潮资讯**（法定披露平台）：

```
POST http://www.cninfo.com.cn/new/hisAnnouncement/query
  column=sse&plate=sse&stock=600377,gssh0600377&category=category_ndbg_szsh
```
=> 一次拿到 2022–2025 四份年报的 PDF 直链。

**另一个坑**：该 API 的 `category` 与 `plate` 参数**必须都给**，
否则 500。（W47 之前我只给了部分参数，误判为"API 不可用"。）

## 六、★ 本期正面经验

1. **"已知答案的极端情形"自检救了一次大事故** ——
   单车真空测试抓出了让整台 CA 静止的 bug，
   而两项"常规"自检（单调性、自由流速度）都**部分通过**；
2. **自相矛盾的输出当信号用** —— "远未饱和"与"饱和度 1.557"打架，
   直接指向一个测错对象的函数；
3. **不合理值当信号用** —— 车均收入 10.4 元 < 最低收费 25 元，
   抓出了"北接线当桥体"；
4. **用官方数字反过来验证自己的分解** ——
   "由大桥降幅反推客车分流率 20.67%"与"独立算出的隧道占比 21.68%"
   只差 **1.0 个百分点**，是很强的内部一致性证据；
5. **CSV/JSON 全部落盘 + 汇总脚本机器生成** ——
   虽然 3.6 出了一次错，但正因为是脚本生成，**错误可见且可修**，
   手抄则无从发现。
