## 三、★ 途中发现的共享 bug：`to_tts` 读错五位以上整数

**发现路径**：重合成对照的输出里看到 `二零二一年八八千一百二十辆`
—— **"八八千"读起来是重复的**。

| 输入 | 修复前 | 修复后 |
|---|---|---|
| `88120辆` | `八八千一百二十辆` | **八万八千一百二十辆** |
| `99058辆` | `九九千零五十八辆` | **九万九千零五十八辆** |
| `65744辆` | `六五千七百四十四辆` | **六万五千七百四十四辆** |
| `105500辆` | `一零五千五百辆` | **十万五千五百辆** |

**根因**：`_int_read()` 的 `units = ["", "十", "百", "千"]` **只有四位**，
五位以上 `pos >= len(units)` => **单位被静默省略**。

**修法**：新增 `_int_read_big()` —— 四位一组 + 万/亿/兆，
组内**补足 4 位后逐位**判零。
**并加了 15 例自检 `selftest_int_read()`** —— 它当场抓出我自己的 2 个 bug：
① 把 `零` 当组间分隔符（`10001` 读成 `一万一`）；
② `pending_zero` 跨组残留（`105500` 读成 `十万零五千五百`）。

详见 `episodes/2026-W46/_logs/to_tts大数bug.md`。

> **影响面**：只有 **W47（5 条）** 与 **W50（B站 4 条）** 有五位以上数字；
> W38–W45 / W48 实测**无**此类数字 => 不受影响。

## 五、教训

1. **"字幕变口播"这个病的根因是同一个**：`add_voice` 兜底分支优先取 `tts`。
   W46 修过一次（改兜底 + 补 `tts_captions`），
   但 **W47 的清单是在修复之前生成的** => 仍然带病。
   => **修了共享脚本，要回头检查"在修复之前生成"的期**。
2. **重合成对照是"一石二鸟"**：它既验同步，
   又把 `say` **读出来给人看** —— 大数 bug 就是这样被**眼睛**发现的。
   只看清单文本（`八八千一百二十`）未必会注意到，
   **因为它"长得像中文"**。
3. **纯函数的转换必须配边界用例**。`to_tts` 之前只有零散手测
   （试过 `47`、`1337`、`2026`），所以 `88120` 这种"看起来很普通"的量级
   一直没人试。加自检后**当场抓出 2 个我自己的 bug**。
4. **静默回退要有护栏**。硬编码的"内置快照"跨期复用 = 定时炸弹
   （W48 已炸过一次）。现在缺配置**直接报错**。
