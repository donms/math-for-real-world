# 173 个数学结果，谁都看不完

## —— 从 86924 个 Lean 模块的依赖图，看一个证明的承重结构与验证成本

---

## 摘要

2026 年 10 月，OpenAI 发布 `openai/math` 仓库，其中 `lean/formalization.yaml` 列出
**173 个形式化条目**，涵盖从唯一游戏定理到多个猜想反例的结果。**这个规模本身
造成了认知障碍**：逐个理解在时间上不可行。

本文改换入口：**不评判结果真伪，只分析其"结构"**。我们从仓库 tarball 中
**流式抽取**全部 `.lean` 文件的 `import` 依赖，得到一张
**86924 个模块 / 248871 条边**的有向图，并通过五项体检
（**DAG 性 86924/86924、悬空边 0.1%、自环 0、外部依赖 17.5%、领域覆盖 21 个**）。

三个主要发现：

**① 跨领域依赖仅占 0.80%。** 204939 条内部边中只有 1648 条跨越数学领域。
=> 这些结果**不是一棵大树的分支，而是上百棵各自独立的树** ——
**理解一个结果对理解另一个几乎没有帮助**。这把"读不完"的直觉变成了可测量的数字。

**② "局部稀疏 + 全局极深"。** 入度中位数为 **1**，而最长依赖链达 **450 层**。
=> 每个模块平均只依赖 1–2 个上游（局部可理解），但串联叠出极深的层级。
**验证成本的直接含义是：局部便宜，整体昂贵。**

**③ 唯一游戏定理专项（数据 100% 完整）：`theorem : lemma = 10694 : 7`。**
该证明由 **479 个模块 / 10701 条声明**构成，最长依赖链 **50 层**；
其**承重墙全部位于 `Machines` 子模块**（`MachineCompositionLemmas` 被 38 个模块依赖、
`MachineSubroutineLemmas` 被 34 个）。=> **这份证明的主体工作是构造并验证一台
图灵机的行为，而非调用现成的深层数学定理** —— 这解释了 144 个 `Machines` 文件的存在。

**关键词**：Lean 形式化 · 依赖图 · 承重分析 · 最长路径 · 验证成本

## 一、问题重述

### 1.1 背景

**2026 年 10 月 6 日**，OpenAI 发布 `openai/math` 仓库，同时
`Quanta Magazine` 于 **10 月 7 日**报道[1]：在"传闻中的 AI 证明"阴影下，
三位计算机科学家抢着发表了自己的里程碑结果。

仓库的 `lean/formalization.yaml` 列出 **173 个形式化条目**，
其中**第 161 条为 `The Unique Games Theorem`**。Lean 中的形式陈述为：

```lean
theorem theorem11 (ε δ : Real) (hε : 0 < ε) (hεhalf : ε < 1 / 2) ... :
    Nonempty (Explicit.MachineOutputContract.BinaryGapReduction ε δ)
```

即"对任意固定的误差对，3SAT 可在多项式时间内归约到唯一游戏"——
**这正是唯一游戏猜想（UGC）的原始表述，且作为已证明的定理给出**。

### 1.2 本文要解决的问题

**173 个结果横跨代数几何、数论、组合、拓扑、表示论。逐个理解在时间上不可行。**

于是本文不问"这些结果对不对"（那需要领域专家阅读 1071 MB 源码，
**不是数学建模能回答的**），而问：

> **这份证明体系的"承重结构"长什么样？**
> **哪些模块是地基、哪些是专为某个结果搭的脚手架？**
> **一个结果的验证成本，能不能从图上算出来？**

### 1.3 五个问题

| 问 | 任务 |
|---|---|
| **1** | **图体检**：这张依赖图能不能用？ |
| **2** | **承重分析**：哪些模块被依赖最多？哪些是瓶颈？ |
| **3** | **领域协作**：每个结果依赖多少"外来"数学？ |
| **4** | **验证成本**：最长推理链有多长？ |
| **5** | **专项**：唯一游戏定理那一支的完整结构 |

## 二、模型假设与合理性论证

| # | 假设 | 合理性 | 若违反的后果 |
|---|---|---|---|
| **A1** | **`import` 边代表"知识依赖"** | Lean 强制：不 `import` 就不能引用其中的声明 | 低估依赖（tactic 内的引用未计入）=> 链长是**下界** |
| **A2** | **依赖图是 DAG** | `import` 在语言层面禁止循环 | **已实证检验：拓扑访问 86924/86924** |
| **A3** | **模块名可映射到数学领域** | 命名约定 `OAI.<Domain>.<...>` | 少量模块归入"(其他)" |
| **A4** | **`theorem`/`lemma` 是主要的知识载体** | 二者是 Lean 的命题声明 | `def`/`structure` 未计入 => 声明数**低估** |
| **A5** | **tar 流顺序 = 仓库目录顺序** | tar 由 git archive 生成 | **导致尾部覆盖不足**（见 §8.1）|

> [!] **A1 与 A4 都会让我们的数字偏小**，故所有规模类结论
> **只报"下限"**（见 §8）。

## 五、问题 2：承重结构

### 5.1 入度分布（**高度偏斜**）

| 统计量 | 值 |
|---|---|
| **中位** | **1** |
| 均值 | **2.36** |
| **最大** | **572** |
| 零入度 | **642**（0.7%）|
| 入度 $\ge 100$ | **96** |
| 入度 $\ge 10$ | **1294** |

**=> 中位数只有 1** —— 绝大多数模块**只被 1 个模块依赖**，
即"**专为某条链服务**"；而少数模块被上百个模块依赖，即"**地基**"。

### 5.2 直接承重 Top 6

| 模块 | 入度 |
|---|---|
| `Analysis.Laughlin.FourBody.RowCompute` | **572** |
| `Analysis.MutuallyUnbiased.MixedSemantics.Rules` | 414 |
| `Analysis.MutuallyUnbiased.MixedSemantics.Permutation` | 411 |
| `Combinatorics.EditApproximation.Definitions` | 399 |
| `Analysis.TracialSplitting.PreparedBlocks` | 350 |
| `Analysis.MutuallyUnbiased.PairSemantics.Permutations` | 319 |

### 5.3 ★ 总承重（反向可达）与一个**反直觉**的结果

| 模块 | 入度 | **反向可达** |
|---|---|---|
| `Analysis.MutuallyUnbiased.MixedSemantics.Code` | 226 | **1828** |
| `Analysis.MutuallyUnbiased.MixedSemantics.Rules` | 414 | **1606** |
| `Analysis.MutuallyUnbiased.MixedSemantics.Nodes82` | 205 | 1311 |

**注意第二行与第一行**：
`Rules` 的**入度（414）几乎是 `Code`（226）的两倍**，
但**总承重（1606）反而更低**。

**原因**：`Code` 处在**更靠下的层**，它的下游还会继续分叉。

> => **入度与反向可达是两个不同的问题，必须并列报告。**
> 只看入度会得出"`Rules` 最重要"，只看总承重会得出"`Code` 最重要"——
> **两个都对，但都不完整。**

### 5.4 ★★ 结构诊断：**局部稀疏 + 全局极深**

$$
\boxed{\ d^-\text{中位} = 1 \quad\text{而}\quad L = 450\ }
$$

**这两件事同时成立，说明这个证明是"模块化"的**：

* 每个模块**只依赖极少数**上游（中位 1）=> **局部可理解**；
* 但依赖**串联下去**叠成 450 层 => **全局理解需要极长的串行链**。

**=> 对验证成本的含义**：
**局部验证便宜（一次只看 1–2 个依赖），整体验证昂贵（要串 450 层）。**

#### 7.2.1 ★★★ `theorem : lemma = 10694 : 7`

**数学论文与教科书的常态**是"大量小引理 + 少量主定理"。
而这里**几乎不用 `lemma`**（10701 条声明里只有 7 条）。

**三个可能的解释（必须并列，不能只挑一个）**：

| # | 解释 | 本数据可否检验 | 结果 |
|---|---|---|---|
| **A** | **机械生成风格** —— 统一用 `theorem` 声明所有命题 | 可 | **支持**（见下）|
| **B** | **`lemma` 被 `theorem` 替代** —— 二者语法等价 | **不可** | **静态文本无法判断** |
| **C** | **命名体系不同** —— 用结构化命名而非 `xxx_aux` | 可 | **部分支持** |

**命名模式的定量检验**：

* 名字**下划线段数中位 2、均值 2.50** => 以"两段式"为主；
* **尾段高度集中**：`le` **587** / `eq` **304** / `iff` **215**
  => **命名模板化** => **支持假说 A**；
* **首段也集中**：`card` 181 / `exists` 150 / `update` 143 / `output` 140
  => 命题围绕少数对象展开 => **部分支持假说 C**。

> [!] **假说 B 必须如实声明为"本数据无法检验"**，
> 不能因为 A、C 有支持就默认 B 不成立。

## 八、敏感性分析、失败与迭代

### 8.1 ★★ 失败一：第一版抽取**丢了 73% 的数据**（静默）

**症状**：全量扫完 **2016.7 MB / 115894 个 `.lean`**，抽出
**theorem 1101212 / lemma 1342346 = 244 万条声明**，
但**落盘只有 29951 个模块**。

**根因**：脚本只在**两处**写文件 ——① 捕获异常时；②**循环正常结束后**。
而第 ② 处要序列化十几万模块的 JSON，**耗时几十秒 —— 超时恰好落在这里**。
日志里那句"已落盘 29951 个"其实来自**异常分支**的旧数。

**修法**：改为**每 1500 个 `append` 一次**（写放大 $O(1)$）。
**修完后同样 5 次超时中断，数据从 29951 涨到 41272，一行没丢。**

> **通用教训：长任务的落盘时机必须与超时风险匹配。**
> 「结束时统一写」在大数据量下**等于不写** ——
> 因为**最可能中断的时刻，正是最需要写的时刻**。

### 8.2 ★★ 失败二：顺序流的**尾部覆盖问题**

**症状**：tar 是**顺序流**，中断后重试**必须从头扫** =>
**越靠后的模块越抽不到**。而 `UniqueGames` 恰好在中后段，
只抽到 **1/479（0.2%）** —— **头条证据的核心部分恰好没覆盖到**。

**修法**：**弃 tar 流，改用"已知模块名 → 算文件路径 → 定向取"**。
（已有的 `imports.jsonl` **就是**那份清单，不需要再列目录。）
=> **479/479，零失败**。

### 8.3 敏感性：覆盖率对结论的影响

| 分析 | 覆盖率 | 是否可给完整结论 |
|---|---|---|
| 依赖图（问 2/3/4）| **58.8%** | **规模类只报下限**；结构类自洽 |
| 声明级（全量）| **47.5%** | 同上 |
| **UGC 专项（问 5）** | **100%** | **可给完整结论** |

> => 本文的**所有绝对规模数字都是下限**，
> 但**结构性结论**（跨领域占比、入度偏斜、最长链量级）
> 在子集内**自洽且方向稳健**。

## 九、模型的评价与推广

### 9.1 优点

1. **数据获取不依赖 API 配额** —— 流式解析 tarball，可复现；
2. **体检完备** —— DAG 性、悬空率、自环、外部依赖占比全部量化；
3. **区分了"直接承重"与"总承重"** —— 并证明二者会给出**不同**的排序；
4. **一处 100% 完整的数据**（UGC 专项）支撑了最具体的结论。

### 9.2 缺点与未做

| # | 未做 | 影响 |
|---|---|---|
| 1 | **未解析 `namespace`** | 记录的是局部名；重名率 13% 与此有关 |
| 2 | **未抽 `def`/`structure`/`instance`** | 声明数低估 |
| 3 | **未做 tactic 级引用分析** | 推理链是**模块级**的 |
| 4 | **未做介数中心性** | 只报了入度与反向可达 |
| 5 | **覆盖率不完整** | 规模类数字为下限 |
| 6 | ★★ **完全不评判结果真伪** | 真伪需领域专家阅读源码 |

### 9.3 推广

本文的方法可直接迁移到**任何形式化数学库**（Lean `mathlib`、Coq、Isabelle）：

* **"承重分析"** 可用于评估一个库的**维护风险**（哪些模块改动影响面最大）；
* **"最长依赖链"** 可用于**验证成本的先验估计**；
* **"跨领域占比"** 可用于判断一个库是**"深井"还是"平原"**。

## 十、结论

1. **这份证明体系是"上百棵独立的树"，不是一棵大树。**
   跨领域依赖仅 **0.80%** —— 这解释了为什么 173 个结果读不完。

2. **它局部稀疏（入度中位 1）但全局极深（最长链 450 层）。**
   => **局部验证便宜，整体验证昂贵。**

3. **唯一游戏定理那一支（100% 完整数据）的承重墙是"图灵机组合"引理**，
   不是某个深层数学定理 => **主体工作是构造与验证一台机器的行为**
   （144 个 `Machines` 文件、10694 条 `theorem`）。

4. **本文不评判这些结果的真伪** —— 那是领域专家的工作。
   本文提供的是**结构性的、可复核的、可推广到其他形式化库的**分析框架。
