## 零、口径（**先读这一节，否则后面全部会误读**）

| 项 | 定义 |
|---|---|
| **边方向** | `A` import `B` => 边 **`B -> A`**（B 被 A 依赖）|
| **入度** | 被多少个模块**直接** import |
| **反向可达** | 有多少模块**传递地**依赖它 |
| **层号** | 从最底层到该模块的**最长依赖链步数** |
| ★ **推理链口径** | **模块级**最长依赖链，**不是"证明步骤"** |

> [!] **第 4 条必须写进论文。**
> 要做"定理 A 用了引理 B"，必须解析 Lean 的 tactic 块
> （引用方式太多：`exact foo`、`simpa using foo`、`rw [foo]`…）。
> **本问不做** => 所有"链长"都指**模块间**的依赖深度。

## 二、★ 问 2：承重结构 —— **局部稀疏、全局极深**

### 2.1 入度分布（**高度偏斜**）

| 统计量 | 值 |
|---|---|
| **中位** | **1** |
| 均值 | **2.36** |
| **最大** | **572** |
| 零入度模块 | **642**（0.7%）|
| 入度 >= 100 | **96** 个 |
| 入度 >= 10 | **1294** 个 |

**=> 中位数只有 1** ——
**绝大多数模块只被 1 个模块依赖**，即"**专为某条链服务**"；
而少数模块被上百个模块依赖，即"**地基**"。

### 2.2 直接承重 Top（入度最高）

| 模块 | 入度 |
|---|---|
| `Analysis.Laughlin.FourBody.RowCompute` | **572** |
| `Analysis.MutuallyUnbiased.MixedSemantics.Rules` | 414 |

| `Analysis.TracialSplitting.PreparedBlocks` | 350 |

| `NumberTheory.Catalan.Analysis.ManuscriptNormLogVGroups` | 238 |
| `Analysis.MutuallyUnbiased.MixedSemantics.Code` | 226 |

### 2.3 ★ 总承重（反向可达）

| 模块 | 入度 | **反向可达** |
|---|---|---|
| `Analysis.MutuallyUnbiased.MixedSemantics.Code` | 226 | **1828** |
| `Analysis.MutuallyUnbiased.MixedSemantics.Rules` | 414 | **1606** |
| `Analysis.MutuallyUnbiased.MixedSemantics.Nodes82` | 205 | 1311 |
| `Analysis.MutuallyUnbiased.MixedSemantics.Nodes42` | 205 | 1290 |
| `Analysis.MutuallyUnbiased.MixedSemantics.Nodes63` | 205 | 1309 |
| `Analysis.MutuallyUnbiased.MixedSemantics.Permutation` | 411 | 1077 |
| `Combinatorics.EditApproximation.Definitions` | 399 | 1040 |

> **入度 ≠ 总承重。**
> `MixedSemantics.Rules` 的入度（414）比 `Code`（226）**高近一倍**，
> 但总承重（1606）**反而更低** ——
> 因为 `Code` 处在**更靠下的层**，它的下游还会继续分叉。
> => **两个指标必须并列报告**，只看一个会得出不同结论。

### 2.4 ★★ 结构诊断：**局部稀疏 + 全局极深**

$$
\text{入度中位} = 1 \quad\text{而}\quad \text{最长链} = 450
$$

**这两件事同时成立，说明这个证明是"模块化"的**：

* 每个模块**只依赖极少数**上游（中位 1）=> **局部可理解**；
* 但依赖**串联下去**叠成 450 层 => **全局理解需要极长的串行链**。

**=> 对"验证成本"的直接含义**：
**局部验证便宜（一次只看 1–2 个依赖），整体验证昂贵（要串 450 层）。**

### 3.3 这条结论**推翻了直觉**

**直觉**：像"唯一游戏定理"这样的结果，应该**广泛调用各门数学**。

**数据**：**跨领域边只占 0.8%** =>
**几乎每个结果都自成一个"领域内闭环"**。

**=> 这解释了为什么"173 个结果"会让人读不完**：
它们**不是一棵大树的不同分支，而是 173 棵各自独立的树**。
**理解一个结果，对理解另一个几乎没帮助。**

> 这是本期**最有解释力的一条发现** ——
> 它把用户的直觉（"很难了解都解决了什么"）**变成了一个可测量的数字**。
