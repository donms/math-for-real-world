## W52-1 ★★★ **同一个坑踩了三次：标识不唯一**

**这是本期最主要的教训，也是全系列最高频的坑。**

| # | 位置 | 键 | 后果 |
|---|---|---|---|
| 1 | `q1_cross_domain.py` 族级 | 用**族名** | **427 个族塌缩成 420**（跨学科重名 7 个）|
| 2 | `q7_shared_or_private.py` v1 | 用**族名**当"用户" | 跨学科重名 **7** 个被误并成一个用户 |
| 3 | W50 的 `imports.jsonl` | 用**名字前缀** | "名字前缀相同就当成同一个模块"（W50 已记）|

### 根因

**"名字"在多层命名空间里不唯一。** Lean 的模块路径是
`OAI.<学科>.<族>.<模块>`，而 `<族>` 这个层级**会跨学科重名**。

### 修法

**唯一键必须是"足够长的路径前缀"**：

```python
def key3(mod: str) -> str | None:
    r"""`OAI.<学科>.<族>.<...>` -> `学科.族`（唯一用户标识）。"""
    m = re.sub(r"^lean\.", "", mod)
    if not m.startswith("OAI."):        # ★ 必须限定命名空间
        return None
    p = m.split(".")
    return f"{p[1]}.{p[2]}" if len(p) >= 3 else None
```

### 教训（**三条**）

1. **用名字做键之前，先量一下重名数量**，并把它当作**数据质量指标**报出来。
2. **`startswith` 必须带命名空间前缀**（`OAI.`），
   否则 `Mathlib.Probability.X` 会被当成一个"族"。
3. **交叉验证**：同一个量用**两份独立实现**算，数字必须相等。

## W52-2 ★★★ **判据是"同义反复"（恒等式）**

### 现象

`q1` 报「**单学科族 413 / 420 = 98.3%**」。

### 根因

原判据是"统计族**自己目录下**出现过几个学科"：

```python
fam_discs[fam].add(dc)     # dc = 该模块**自己所在**的学科
```

**但每个族只属于一个学科目录** => 这个集合**恒为 1**
=> `dist` 永远是 `{1: 420}` => **98.3% 是复述定义，不是发现**。

### 修法

**判据必须沿依赖方向**：

$$\mathrm{Cross}(F) = \{\, d \;\bigm|\; \exists m \in F,\ \exists p \in \mathrm{deps}(m):\ d = \mathrm{disc}(p) \neq \mathrm{disc}(F) \,\}$$

```python
for dp in deps_of.get(mod, []):
    p2 = mod2dc.get(dp)
    if p2 and p2[0] != dc:          # ★ 关键：与**本族**学科比较
        fam_dep_discs[key].add(p2[0])
```

**修正后**：完全不跨学科 **381 / 427 = 89.2%**（从 98.3% 变成 89.2%）。

### 教训

> **写完一个统计量，先问："它的取值能不能不是这个数？"**
> 如果答案是不能，那它**没有信息量**。

**自检方法**：把判据套到一个**随机构造的数据**上，
若输出恒定 => 判据退化了。

## W52-3 ★★ **"同学科"与"跨学科"混用（差一个"1 减"）**

### 现象

文档里写：

> 「按学科规模，**随机一对模块本可以跨学科的概率 = 17.44%**，
> 实际 0.45% => **低约 39 倍**。」

**这句是错的。**

### 根因

`17.44%` 是 **M0 下「同学科」的期望概率**（$=\sum_d p_d^2$），
**不是**跨学科的期望。

| 口径 | 值 |
|---|---|
| M0：**同科**概率 $=\sum_d p_d^2$ | **17.44%** |
| **M0：跨科**概率 $=1-\sum_d p_d^2$ | **82.56%** |
| **实际观测**跨科率 | **0.45%** |
| **倍数** | **185 倍**（不是 39）|

### 修法

* 把解析值写进 `q3_零模型.json` 的 `m0_analytic` 字段，供交叉核对；
* **全局修正 6 处**（结论速览 / 选题卡 / 题面 / q3 报告 / q4 脚本注释）；
* **在题面里加了这个陷阱的警告**（因为它是个好考点）：

> [!] 零模型输出的通常是"**同学科**占比"，而你要比的是"**跨学科**率"
> —— **两者相差一个"1 减"**，搞错会让倍数差 5 倍（39 vs 185）。

### 教训

> **"同科率"和"跨科率"是一对互补量，写数字时必须显式写出用的是哪一个。**
> 凡是「同 X 率 / 跨 X 率」并存的场合，都要在变量名里带上方向。

**旁证**：解析值 $\sum_d p_d^2$ 与置换模拟的均值**完全一致（都是 17.44%）**
=> 说明**模拟没错，是我读错了方向**。
**=> 交叉核对能定位到"哪一步错了"，而不只是"错了"。**

## W52-4 ★★ **"含自己学科"与"排除自己学科"两个口径混用**

### 现象

同一份数据算出 **29 个跨学科族**（`q17`）与 **12 个**（`q1`），
而**代码逻辑看起来等价**。

### 根因

| 口径 | 定义 | >=2 个学科 |
|---|---|---|
| **含自己学科** | 依赖到的**所有**学科数 >=2 | **29** |
| **排除自己学科** | 借用了 >=2 个**别的**学科 | **14**（后核为 12）|

实际差异来自**"同学科跨族"算不算跨学科**：

| 族 | 含自己 | 排除自己 | 说明 |
|---|---|---|---|
| `Algebra.FinitisticAsymmetry` | `['Algebra']` | `[]` | **用了同学科的另一个族** => 不算跨学科 |
| `Analysis.CircleDomains` | `['Analysis','Geometry']` | `['Geometry']` | 真跨学科 |

### 修法

**两个口径都对，但必须在每个数字旁标明用哪个。**
本期定稿：

* **问 1 用"排除自己学科"**（回答"借了几个别的学科"）；
* **问 8 用"含自己学科"**（比"跨 vs 不跨"）。

并在结论速览里加了**专章"口径澄清"**。

### 教训

> **同一份数据在同一篇报告里出现两个口径，是最容易让读者误判的地方。**
> **要么统一，要么在每个数字旁标注。**

## W52-5 ★ **"观测超过我设的零模型"不能证明强结论**

### 现象

初版结论写：

> 「观测 99.55% **远超**最保守零模型 M2（99.50%）=> **聚类显著**。」

### 根因

**M2 里的"0.995 同学科偏好"是我自己设的参数**，不是从数据推的。
=> "观测 > M2" **只说明"偏好 > 0.995"这件事不成立**，
**完全不能**用来证明"壁垒很强"。

### 修法

明确区分**干净基准**与**含人为参数的基准**：

| 零模型 | 性质 |
|---|---|
| **M0 完全随机** | ★ **解析可算**（$\sum_d p_d^2$）=> **干净基准** |
| M1 保出度 | 干净（只打乱目标端）|
| M2 强同学科偏好 | **含人为参数** => 不能用于证明 |

**并给出正确表述**：实际跨科率比 M0 低约 **185 倍**。

### 教训

> **零模型里凡有"我设的参数"，那个模型就只能当"下界检验"，
> 不能当"上界证明"。**
> **如果一个模型无论数据怎样都能被"超过"，那它没有检验力。**

## W52-6 ★ **"共享底座"与"桥梁"不是一回事**

### 现象

主结论一出来，最强的反驳是：

> "所有模块都 import mathlib，mathlib 覆盖全部数学分支
> => 它们**间接**都用了跨领域知识。"

**若不处理这个反驳，主结论不成立。**

### 修法

**关键区分**：

| 概念 | 含义 | 费马大定理需要的是？ |
|---|---|---|
| **共享底座** | 两个学科都用 mathlib 的集合论 | [X] |
| **桥梁** | 椭圆曲线引用模形式的**具体定理** | [OK] |

**检验设计**：对每个学科算依赖**闭包**，比较
「含 mathlib」与「剔除 mathlib」两种口径下可达的学科数。

**结果**：**下降的学科 = 0 / 17** => 反驳不成立。

### 教训

> **"都用同一个底层库"!="互相引用"。**
> 度量"桥梁"必须**排除共享底座**，否则会把
> "所有人都用集合论"误算成"数学高度统一"。

## W52-7 ★ **模块名不可信，必须读源码**

### 现象

`Combinatorics.SumProduct`（**903 条跨科跨族边里最大的一对的一半**）
的子模块名全是通用词：

```
Alignment.AbelianMalcev01 / Admissible01 / AffineOrbit01 /
AlignmentMass01 / AllLevel01 … AllLevel08
```

**看起来就是个工具库。**

### 但实际上

读源码后发现：

* **259 个模块 / 只有 1 个子族**（工具库会有多个平行子族）；
* **外部引用方只有 1 个族**（工具库会被多个不相关的族引用）；
* `CONTENTS.md` 里对应 **[164] Hindman's finite sums and products conjecture**；
* 源码里是 namespace `TorusLeibman`、`polynomialOrbit : (ι -> Polynomial R) -> N -> UnitAddTorus ι`。

**=> 它是一个具体数学问题的研究项目，不是工具库。**

### 教训

> **目录名和模块名只反映"组织方式"，不保证反映"数学内容"。**
> **凡是要下"这是什么"的判断，都要读源码或读官方文档。**

**并且**：依赖方向必须**显式测量**
（`a2b = 263, b2a = 0`）—— 不测就写"跨领域合作"是**不准确的**。

## W52-8 **PowerShell here-string 会吞掉 Python 的引号（工具链坑）**

### 现象

用 `pwsh -Command` + `@"..."@` 写 Python 补丁时：

```powershell
& python -c @"
s = s.replace('old', 'new')     # 报 SyntaxError
"@
```

**报 `SyntaxError: invalid syntax` 或 `unterminated triple-quoted string`。**

### 根因

PowerShell 的 here-string **会解释内部的引号**，
与 Python 的字符串引号冲突。**三引号 `'''` 尤其容易碎。**

### 修法

**凡是"写文件"或"改文件"的操作，一律用 `write` / `edit` 工具**，
不要用 PowerShell 里嵌 Python 的方式。

**PowerShell 只用来"跑脚本"和"查状态"**。

### 教训

> **工具选错会让"改一行"变成"试四轮"。**
> 本期为此浪费了 **4 轮**（三引号碎 2 次、f-string 引号被吞 2 次）。

## W52-9 **画图时 markdown 标记会变成字面量**

### 现象

`ax.set_title(f"... -> **显著**")` 画出来是 `-> **显著**`，
**星号被当字面量画在图上。**

### 修法

**画面文字里不能出现 markdown 标记。**
加一个**自动检查**：

```python
for m in re.finditer(
        r'(?:set_title|set_xlabel|set_ylabel|ax\.text|'
        r'set_xticklabels|label=)\s*\(?[^)]*?\*\*', src):
    print(f"[!] L{line}: {m.group(0)[:80]}")
```

### 教训

> **"写进 md"和"画进图"是两套格式，不能共用字符串。**
> 凡是把带 markdown 的文本传给绘图 API，先剥标记。

## W52-10 **坐标轴色阶范围必须覆盖真实数据范围**

### 现象

归一化矩阵图（观测 / 期望）用 `vmin=-1.5` 之后，
**非对角部分全部被压成同一档深蓝**，块对角结构**完全看不出来**。

### 根因

非对角比值范围是 $5.0\times10^{-4}$ 到 $1.09$
=> $\log_{10}$ 范围是 **$-3.3$ 到 $0.04$**，
而色阶只到 $-1.5$ => **饱和**。

### 修法

先**算真实范围再定色阶**，并把范围打印出来：

```python
nz = Ro[(Ro > 0) & ~np.eye(N, dtype=bool)]
print(f"非对角比值：min={nz.min():.2e} 中位={np.median(nz):.2e} "
      f"max={nz.max():.2e}")
im = ax.imshow(np.log10(Ro + 1e-6), vmin=-4.5, vmax=3.5)
```

### 教训

> **色阶饱和是最隐蔽的"图错了"** —— 图能画出来、看着正常，
> **但信息全丢了。**
> **定色阶前先打数据范围。**

## W52-11 **单位不同的量不能放在同一根轴上**

### 现象

"桥梁四层漏斗"图里，前三层是**边数**（204200 / 909 / 903），
后两层是**模块数**（317 / 301），**全画在同一根 x 轴上**。

### 修法

加**单位分隔虚线 + 标注**，并在标签里写出单位：

```python
ax.axhline(2.5, color=C["darkred"], lw=1.4, ls=":")
ax.text(..., "^ 以上单位：边　　v 以下单位：模块", ...)
```

### 教训

> **漏斗图常把"不同单位的量"串成一条链。**
> 若单位变了，**必须在图上标出来**，否则读者会当成一个连续的收敛过程。
