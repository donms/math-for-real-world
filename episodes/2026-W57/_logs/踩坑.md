## W57-1 ★★★ `ECBMRRFR` 缺 2001–2007 整七年，而所有体检指标都正常

**症状**：欧元区那一路跑 1999–2026 的回归，输出 `n = 77`，
样本区间标着 `1999Q1–2026Q2`。**数字本身毫无异常**：
点数合理、标准误合理、判定合理。差点就这么写进论文。

**根因**：`ECBMRRFR`（欧央行主要再融资操作利率，日度）有 3031 个缺失值
（占 29.8%）。而 `n_missing` 这种指标**只报"一共几个缺失"，看不出缺失是散的还是连片的**。实际结构是：

| 年份 | 有值天数 / 总天数 |
|---|---|
| 1999 | 365 / 365 |
| 2000 | 179 / 366 |
| **2001–2007** | **0 / 各年全部** |
| 2008 | 78 / 366 |
| 2009–2026 | 100% |

我的 `monthly_series()` 按"月序号"建字典，**没有观测的月份直接不出现**，
于是那七年整段消失；而样本区间仍显示 `1999Q1–2026Q2`，
因为首尾两端都有值。**这是一个两端完好、中间掏空的序列。**

**修法**：加一道**按年计数扫描**，把"落在首末年之间、计数为 0 的年份"报出来，
并对主用序列**硬断言**不许有内部空洞：

```python
def interior_gaps(sid):
    per = {}                                  # 年 -> 有值的期数
    for x, y in load_local(sid):
        if y is not None:
            per[int(x[:4])] = per.get(int(x[:4]), 0) + 1
    lo, hi = min(per), max(per)
    return [yr for yr in range(lo, hi + 1) if per.get(yr, 0) == 0]
```

抓到的结果：`ECBMRRFR` 缺 **2001–2007 共 7 年**，其余 11 条主用序列全部干净。

**处置**：主用 `ECBDFR`（存款便利利率，0 缺失、1999-01-01 起连续），
`ECBMRRFR` 只在 2009 年之后（该段完整）当稳健性用。

> ★★ **教训：`n_missing` 与"缺失率"都只能告诉你"丢了多少"，不能告诉你"丢在哪"。凡是时间序列，必须再做一次"按年/按季计数"的扫描，因为连片缺失会让样本量看起来完全正常，而时间区间看起来也完全正常。**这是本期唯一一个"不修就悄悄错"的坑。

## W57-2 ★★ `GDPPOT` 与 `NROU` 带 CBO 到 2036 年的**预测**

**症状**：`GDPPOT` 的末值是 `2036-10-01`，而实际 GDP 末值是 `2026-04-01`。
拿它直接算产出缺口，2026 年之后那 40 个季度的"缺口"是
"用未来的潜在产出去除现在的 GDP"，**分母与分子不是一个时点**。

**根因**：CBO 的潜在产出与自然失业率估计**本身就含向前预测**，
FRED 把这些预测也一起发布了，且**没有任何字段标注哪一段是预测**。

**修法**：把这类序列按"最后一个真实观测"截断，锚用同频的真实序列：

```python
TRUNC_ANCHOR = {"GDPPOT": "GDPC1", "NROU": "UNRATE"}
```

实测：`GDPPOT` 从 352 行截到 310 行（丢掉 2026-07 ~ 2036-10 共 42 行），
`NROU` 从 352 行截到 311 行。截断结果另存 `*__trunc.csv`，
**原始文件保持不动**，便于复核删了什么。

**防线**：断言 `max(GDPPOT截断后) <= max(GDPC1)`。

> ★ **教训：官方序列不一定"只含历史"。凡是"潜在/自然/趋势"类变量，都要先查它有没有向前预测，再查它止于哪一天。**

## W57-3 ★★★ 自己的断言用错了判据：拿 `YYYY-MM-DD` 解析器读 `YYYYQn` 标签

**症状**：滚动窗口的端点断言报错

```
AssertionError: 滚动窗口端点错：{'end': '2021Q1', 'start': '2011Q2', ...}
```

**根因**：断言写成

```python
assert qi(r["start"]) + ROLL_Q - 1 == r["k_end"]
```

而 `qi()` 是**按 `YYYY-MM-DD` 写的**：它取 `date[5:7]` 当月份。
对 `"2011Q2"` 来说，`date[5:7]` 取到的是 `"2"`，
于是 `qi("2011Q2") = 2011*4 + ((2-1)//3) = 2011*4 + 0`，
**被读成 2011Q1，正好差一季**。而且它**不报错**（`int("2")` 合法），
所以这不是崩溃，是静默算错。

**修法**：判据一律用**整数季序号**，标签只用于显示，并且加一条"标签与序号吻合"：

```python
assert r["k_start"] + ROLL_Q - 1 == r["k_end"]
assert qi_label(r["k_start"]) == r["start"]     # 标签必须能由序号重建
```

**并且**这条断言后来又抓出第二个真问题：剔零下限之后，40 个观测要跨更多日历季度，
`k_start + 39 == k_end` 只在"照算"口径成立。于是判据拆成两支：
照算口径要求 `跨度 == 40`，剔零下限口径要求 `跨度 >= 40`。

> ★★ **教训：断言的价值不在于"能通过"，而在于"它能怎么出错"。这一条断言的价值是它一开始是错的：写错的那一刻就把一个真 bug 暴露了。⇒ 写断言时要问"我这个判据本身可靠吗"，而不是"跑通了就完事"。**

## W57-4 ★★ `statsmodels` 在本机跑不起来，互证方案只能换

**症状**：

```
TypeError: deprecate_kwarg() missing 1 required positional argument: 'new_arg_name'
  at statsmodels/tsa/stattools.py:395
```

在 `import statsmodels.api as sm` 这一步就炸。

**根因**：本机 `pandas 3.0.5` 而 `statsmodels 0.14.2`，
`deprecate_kwarg` 的签名在后者的代码里还是旧用法。**不是我的代码错**。

**处置**：原计划是"手写 HAC 标准误 vs `statsmodels` 的 `cov_type='HAC'`"，
这条路断了。改成两条**同一公式的不同代码路径**：

| 实现 | 做法 |
|---|---|
| `ols_hac` | 先把 $x_t u_t$ 堆成矩阵，一次矩阵乘得 $\Gamma_l$ |
| `ols_hac_loop` | 对 $(t,l)$ 逐个元素双重循环累加，索引写法完全不同 |

两条路径最大偏差 **$2.11\times10^{-15}$**。

**并且**：区间的第二套方法由**循环块 bootstrap** 提供（真·不同统计方法），
这样"方法互证"这一层没有丢。

> ★ **教训：不要为了用某个库而改环境。** 本期如果去 `pip install` 降级 pandas，
> 风险是整个仓库的其它脚本一起坏。正确做法是**把这条互证换成本地能做的等效物，并在文档里写清"为什么没走第三方库这条路"**。

## W57-5 ★★★ 两套都合法的区间给出相反判定，这时报哪一个

**症状**：欧元区全样本 $\hat\phi_\pi=0.188$：

| 区间方法 | 95% 区间 | 判定 |
|---|---|---|
| Newey–West HAC | $[-0.167,\ 0.542]$ | **1 以下** |
| 循环块 bootstrap | $[-0.132,\ 1.047]$ | **跨 1** |

两套方法都合法，结论相反。**挑窄的那一套来讲结论，等于用方法的选择把结论挑出来。**

**修法**：加一条**刻意保守**的合并规则，并写进代码注释：

```python
def verdict_union(a, b):
    """只要有一套跨 1，就判"跨1"。宁可说不知道，不许说知道了。"""
    if "跨1" in (a, b):
        return "跨1"
    return a if a == b else f"不一致({a}/{b})"
```

改判后，13 组设定里 **8 组**判"跨 1"（HAC 单独判 6 组，bootstrap 单独判 8 组）。

**防线**：加断言"两套任一跨 1 ⇒ 合并判跨 1"，逐行校验，
防止将来改代码时把合并规则改漏。

> ★★ **教训：当一个结论依赖于"用哪套区间"，那它本来就不是结论。正确做法不是选一套，而是把"两套不一致"本身当成结果报出来，并按**更保守**的方向合并。**

## W57-6 ★★ 子样本区间窄得反常，那是**退化**不是精度

**症状**：美国 2009–2015（零利率下限）子样本

$$\hat\phi_\pi=-0.014,\qquad 95\%\ \text{区间}=[-0.023,\ -0.004].$$

区间窄到 $\pm0.01$。看起来"估得极准"，而这是**最不准**的一段。

**根因**：这段里 $i_t$ 几乎是常数（被下限顶住），
$\phi_\pi$ 完全由通胀的**极小残余变异**决定。
被解释变量没有变异时，回归的残差方差极小、标准误自然也极小，
**区间窄是退化的症状**。

**修法**：不改模型（这是正确的代数），改**结论的写法**。
`q5` 的结果文档里专列两段：

1. `2009-2015` 那一行**不能**读成"估得准"，要读成"回归退化了"；
2. `2020-2026` 那一行是**负的**（$-0.414$），因为**加息滞后于通胀**
   （通胀 2022 年中见顶，利率 2023 年才到顶），同期回归把"反应滞后"读成"负反应"。

> ★★ **教训：窄区间不总是好消息。先问"被解释变量在这段有没有变异"。一个几乎不变的 $y$ 会给出一个看起来极其精确的系数。**

## W57-7 ★★ 嵌套粗体：`**[...]**` 里再套一层 `**`

**症状**：结果文档的表格出现

```
| 美国 | ... | **[0.676, 1.163] **跨 1**** |
```

双星号两层嵌套，Markdown 的 `**` 计数变成奇数。
按 W54 的教训，这会让 `md2docx.py`（**按行**解析粗体）在 Word 里
**残留字面 `**`**。

**根因**：`fmt_ci()` 返回的字符串里带了 `**跨 1**`，而调用处又用 `**{fmt_ci(r)}**` 包了一层。

**修法**：`fmt_ci()` 只返回**纯文本**，粗体只在单元格那一层加：

```python
def fmt_ci(r, key="ci95_hac"):
    """⚠ 绝不能返回 **...**：返回值会被塞进已经被 ** 包住的单元格。"""
    lo, hi = r[key]
    return f"[{lo:.3f}, {hi:.3f}] {verdict(lo, hi)}"
```

**防线**：交付前跑 `check_md_delivery.py`（查 `**` 个数为奇数）。

> ★ **教训：凡是"生成一段 Markdown 片段"的函数，都要声明它输出的是纯文本还是带标记的。** 一个返回 `**bold**` 的辅助函数，
> 在被复用到另一个加粗上下文里时一定出事。

## W57-14 ★★ 补丁内容里有美元符，就不能经 PowerShell 传

**症状**：往论文里插一段含行内公式的补丁，用 `pwsh -c` 加 here-string 传进去，
PowerShell 报 `在此字符串中缺少终止符: '` / `MissingArgument`。

**根因**：补丁里写的是行内公式（美元符包住 `y,\pi`）。
**`$(` 在双引号里是 PowerShell 的子表达式**，它先把 `y,\pi` 当命令求值，
于是引号配对被破坏，后面全乱。

**修法**：把补丁写成 `.py` 文件（`write` 工具），PowerShell 只负责
`& $PY .workbuddy\tmp\w57_patch_paper.py`。文件里用 `chr(92)` 与 `chr(36)`
拼出反斜杠与美元符，**彻底绕开 shell 的转义层**。

**顺带踩到的第二个坑（同一个补丁脚本内部）**：插入两条新编号公式之后，
文件里会同时存在"新 (18)"与"旧 (18)"，
于是"按编号整体 +2"的循环在 `(19)` 上**命中了两次**。
断言当场抓住：`AssertionError: 编号 (19) 出现 2 次，不能盲目顺延`。

**修法**：**先顺延、后插入**；顺延时从大到小；**每次替换都断言恰好命中一处**。

> ★★ **教训：与 W56-9、W56-17、W57-10 是同一条纪律的第四次确认。并且多了一条新内容：凡"按编号批量替换"，都要先做"旧编号全量唯一"的断言，否则插入与顺延的先后顺序会静默改错。**
> **这一条的本质是"顺序依赖"**：插入会制造重复键，
> 而批量替换假设键唯一。**两个都对的步骤，换个顺序就错。**

## 视频阶段的四条（W57-15 ~ W57-18）

## W57-15 ★★ `duration_factor` 的方向搞反了，三档白跑一轮

**症状**：第一轮标定取 0.80 / 0.88 / 0.96，量出 **81.5 / 73.7 / 64.9 字/秒**，
荒谬到一眼可疑；而目标只有 6.2 字/秒。

**根因有两层，叠在一起**：

1. **分子的口径与分母不是同一批样本**（真正的错）。脚本把整屏 459 字当分子，
   却只把**前两句**送进 TTS，于是时长只覆盖 36 字。这正是 W54-8 那条
   "先验两端各自的构成"的同类错误。
2. **`duration_factor` 值越小越快**（`1.0` 是自然慢速）。我按"0.88 应该更慢"的
   直觉选了档位，方向就是反的。

**修法**：① 返回**实际送进 TTS 的每一段**并据此数字数；
② 三档改成 0.74 / 0.79 / 0.84，实测 **7.04 / 6.64 / 6.21 字/秒**，
选 0.84（偏离目标 +0.01）。

> ★★ **教训：凡是"率"（字/秒、命中率、覆盖率），先问一句
> "分子和分母是不是同一批样本"。** 这类错不会报错，只会给出一个荒诞的数值；
> 而荒诞的数值**恰好是最好的信号** —— 81 字/秒这种量级，读中文是不可能的。

## W57-16 ★★ `bullets` 不是合法的卡片 `kind`，那一屏会静默消失

**症状**：`render_cards.py --ep` 输出里有一行
`[!] 未知卡片类型: bullets`，然后 7 屏只渲出 **6 张**。

**根因**：`render_cards.DRAWERS` 只有
`cover / text / figure / compare / summary / cta / formula / exercise`，
**没有 `bullets`** —— 那是 `render_slides16x9.py`（横屏）才有的版式。
`render_cards` 对未知 kind 是 `continue`（静默跳过），
而清单里那一屏的 `img` 仍然写着 `xhs_05_bullets.png` ⇒ 渲染时**缺图**。

**修法**：竖屏配置（`screenplan_douyin.json`）只用横竖通用的版式；
`bullets` 一律改成 `text`（字段同为 `lines`）。

> ★ **教训：横屏与竖屏的版式清单不是同一套。** 每期写竖屏配置时，
> 先看 `render_cards.DRAWERS` 的键，再决定 `layout`。

## W57-17 ★★ 同一句封面 `sub`，横屏折行、竖屏不折 ⇒ 压在装饰线上

**症状**：`bili_cover.png` 里副标题折成两行，第二行**正好压在 `h*0.56` 那条装饰横线上**；
而 `douyin_cover.png` 与 `xhs_01_cover.png`（同宽 1080）都是一行。

**根因**：`render_covers()` 对两种画布用**不同的折行宽度**：
横屏 `wrap = int(13*1.6) = 20`？不，是 `wrap=10`（横屏）对 `wrap=19`（竖屏），
而两者宽度都是 1080 —— **字号一样、可用宽度一样，折行数却不同**。
`工资涨 5% ＋ 物价涨 5%，你没变富` 在 19 宽下是一行，在 10 宽下是两行。

**修法**：把 `＋` 改成 `，` 并让文案短到**横屏也不折行**。

> ★ **教训：一份封面文案同时供横竖两种画布时，按"最窄的那种折行规则"写。**

## W57-18 ★★ 动画画面的底部不能放字（会被字幕压住 / 进 UI 安全区）

**症状**：splice 之后抽帧，动画底部那行橙色结论
「自我强化发生在时间上，不在相图的旋转上」与字幕**落在同一行**，
看起来像两段文字挤在一起；竖屏更糟，它落在 `y>1440` 的平台 UI 安全区里。

**根因**：片段是**接到成片里**的，而 `render_video` 已经把字幕烧在
`margin_v=58`（横屏）/ `560`（竖屏）处。片段自己再画一行底部文字，
两者必然重叠 —— 这和 W43 那次"抖音卡片 CTA 与字幕相撞"是同一条物理约束。

**修法**：结论性文字一律放进**顶部副标题**或口播；画面底部留白。

> ★ **教训：凡是"会被 splice 的素材"，要按"它下面还有一层字幕"来排版。**
> 这与"卡片底部留白给字幕"是同一条规矩，只是这次踩在了动画上。

### 视频阶段的三处已知限制（**如实记录，未修**）

## W57-19 ★★★ 字幕折行落在标点前：**修在折行里，不是补 ASS**（用户裁决后回填）

> 上面"已知限制"第 1 条**已修**（2026-10-25，用户明确要求"必须修"）。

**症状**：横屏 156 行字幕里 **15 行以标点开头**（「，为宏观稳定政策提供微观基础。」），
抖音 31 行里 **3 行**，其中 **2 行整条只有一个「。」、时长 0.19 s** ——
观众会看到画面**闪一下一个句号**。

**根因**：`render_cards.wrap_cjk` 是**按视觉宽度**折行，它不认识标点的语义，
断点落在逗号之后、就把逗号留在了下一行的行首。

**为什么不能"事后补 ASS"**：`render_video.py` **每渲一次都会重写 ASS**，
补在渲染之后等于补在"烧进画面之后"。⇒ 必须改**折行本身**。

**修法**（`render_video.py` 新增 `fix_punct_wrap()`，在 `wrap_sub()` 出口调用）：

1. **整条只有标点** ⇒ 并进上一条（标点属于上一句）；
2. **行首有标点** ⇒ 把这串标点挂到上一条末尾；若上一条因此超宽，
   从它**末尾**往回挪字到当前行开头；
3. ★ **只挪"非标点"的字** —— 否则挪回来的又是标点，会来回震荡；
4. 单行也要过这一遍（`flat` 那条快速路径原来**直接 return**，会绕过修复）；
5. 兜底：第一行整条只有标点且后面还有行 ⇒ 并到下一行**开头**。

**实测前后三个数**：

| 量 | 修前 | 修后 |
|---|---|---|
| 字幕行数（bili / douyin）| 156 / **31** | 156 / **29** |
| 首字符为标点的行数 | **15** / 3 | **0** / **0** |
| 整条只有标点的条数 | 0 / **2** | **0** / **0** |

（douyin 少 2 行 = 两条只显示「。」的事件被并进前一条；bili 行数不变，
因为那 15 行都还有内容，只是把行首标点还给了上一行。）

**重烧后必须仍然达标的两个数**：`nb_frames` **15357 / 1710**（与修前一致）、
`|视频−音频|` **+0.0000 s / +0.0000 s**（与修前一致）。
⇒ **修字幕不能改时间轴**：本次只动了"一行字显示成几行"，
总时长、帧数、音轨全部未变。

> ★★ **教训：凡是"折行/断句"这类呈现层决策，修在折行函数里才是一次性修好；
> 修在产物上（ASS、PNG）只是把这一版补好，下次重渲又回来。**
> 而且**必须回归"两个不能变的数"**（帧数、音画差）—— 否则"修字幕"很容易
> 顺手把时间轴改掉，而那种改动**不会报错**。
